# sitescope 1.3.0

Groundwork for the next capabilities (`docs/roadmap.md`). Existing
deployments see no change: the production config builds the same checks
as 1.2.0, with the same ids, names, areas, timing and probes.

## Features

- Check modules: each config section (`hosts`, `dns`, `tls`, …) now lives in
  `internal/check` with its defaults and checks. Config keys are unchanged.
- Agent collectors run from a table and skip what doesn't apply. The NixOS
  facts are collected only on NixOS, and `agent.wireguard: false` skips
  WireGuard. The report gains `os` (from `/etc/os-release`).
- Hosts take `os` (default `"nixos"`), `wireguard` (default on), `ca` and
  `tokenEnv`. A non-NixOS host drops the reboot and nixpkgs checks.
- An agent serves HTTPS with `agent.tlsCert` and `agent.tlsKey`, and reloads
  a renewed certificate on its own. The hub verifies it against the host's
  `ca` and sends the token from the host's `tokenEnv`.
- Alerts go through a notifier interface; email is the only notifier so far.

## Bug fixes

- A CT test failed after 2026-10-08 because its fixed certificate date aged
  out of the 7-day window. Tests only.

## Breaking changes

- None. The log lines "mail disabled, not sending" and "sending mail failed"
  are now "notifications disabled, not sending" and "notification failed"
  (with `via=email`).

## Upgrade notes

- Pin the release commit and redeploy; then `sitescope unlock` on the hub host.
- Rollback: two-way. No config or state changes; older hubs ignore the
  report's new `os` field.
- Verify: the footer and `/status.json` show `1.3.0+<rev>`, the check count
  is unchanged, and the next alert or digest arrives by email as before.
