# sitescope 1.7.0

FreeBSD and OpenBSD. The hub and the CLI run on both, and releases include
`freebsd-amd64` and `openbsd-amd64` tarballs beside the Linux ones. On Linux,
existing checks and configuration are unchanged. The one new path is ping's
raw-socket fallback, which Linux takes too if its unprivileged ping socket
is unavailable.

## Features

- The hub and the CLI build and run on FreeBSD and OpenBSD: the vault, the
  control socket, the status page, and every check made over the network.
  Tested natively on FreeBSD 15.1 and OpenBSD 8.0.
- The vault's memory hardening has each system's equivalent of the Linux
  calls:
  - **Buffers kept out of core dumps:** `MAP_NOCORE` on FreeBSD, `MAP_CONCEAL` on OpenBSD.
  - **No same-user ptrace:** `procctl(PROC_TRACE_CTL)` on FreeBSD; on OpenBSD,
    the default `kern.global_ptrace=0`.
  - **Core limit:** zero on both.
- Ping falls back to a raw ICMP socket where the system has no
  unprivileged ping socket. On FreeBSD and OpenBSD that needs root; run as
  an ordinary user, a ping check fails and says so.
- Release tarballs for `freebsd-amd64` and `openbsd-amd64`. CI vets both
  builds on every push.

## Bug fixes

None.

## Breaking changes

None. On FreeBSD and OpenBSD, `sitescope agent` and a hub with a
`local = true` host refuse to start: the agent's collectors read Linux's
`/proc`, `/sys` and systemd.

## Upgrade notes

- Pin the release commit in the infra flake and redeploy, then `sitescope unlock` on the hub host.
- Rollback: two-way; no config, state or report format changed.
- Verify: the footer and `/status.json` show `1.7.0+<rev>`.
- On FreeBSD, raise the login class's `memorylocked` to `1M` (`/etc/login.conf`, then `cap_mkdb`), so the vault's buffers can be locked.
