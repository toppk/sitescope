# sitescope 1.5.0

A strict config. An unknown or misspelled key used to be ignored, leaving
a default in force without a word. Now it stops the hub, the agent and the
CLI from loading the config, and says which key and where.

**Every existing config needs converting** (see Breaking changes). The
checks it builds are unchanged: converted, the same config gives the same
check ids, names, areas, timing and probes as 1.4.2.

## Features

- Strict keys. Every unknown or mistyped key fails at load with its path,
  and the closest known key when one is near. Every problem is listed at
  once:

  ```text
  sitescope: config: 2 problems:
    hosts.swapin: unknown key (did you mean swapIn?)
    host[0].unitz: unknown key (did you mean units?)
  ```

- `sitescope config -config FILE` prints the effective config, with every
  default filled in. With `-check` it only validates the config and builds
  its checks, and prints the count. It needs no secrets and opens no files
  the config names.
- The NixOS module runs `sitescope config -check` on the rendered
  `settings` when the system builds, so a typo fails `nixos-rebuild`
  before anything deploys.
- `"off"` disables a threshold bound (`{"warn": 95, "crit": "off"}`),
  `hub.lockedAfter` and `alerts.unknownAfter`.
- `check` and `probes` take `-format json`, which prints the same facts as
  the text output.
- The usage text is generated from the command table.

## Bug fixes

- `sitescope check -match` fails when no check id matches, instead of
  printing nothing and exiting 0.
- Keys match exactly, case included. Before, `"swapin"` set `swapIn`
  without a word, because Go's JSON decoder ignores case.

## Breaking changes

Each old form fails to load and names its replacement. Convert the config
in the same deploy as the upgrade.

| 1.4 | 1.5 |
|---|---|
| `"hosts": {"hosts": [...], "wgPeers": ..., <thresholds>}` | `"host": [...]` at the top level; `"hosts": {"wgPeers": ..., <thresholds>}` |
| `"hub": {"lockedAfter": "-1s"}` (any negative) | `"hub": {"lockedAfter": "off"}` |
| `"alerts": {"unknownAfter": "-1s"}` (any negative) | `"alerts": {"unknownAfter": "off"}` |
| `"dns": null` (any section set to null) | leave the key out |
| a threshold bound set past any reading, e.g. `"crit": 101`, to disable it | `"crit": "off"` (101 still loads) |
| a key in the wrong case, e.g. `"swapin"` | the exact key, `"swapIn"` |
| any other unknown key | remove or correct it |

In Nix, `hosts.hosts = [ ... ]` becomes `host = [ ... ]`, and the rest of
`hosts` stays where it is.

`sitescope check -match` with no match now exits 1.

## Upgrade notes

- Convert the config, then check it with the new binary before switching:
  `sitescope config -check -config FILE`. On NixOS the system build does
  this.
- Pin the release commit in the infra flake and redeploy, then `sitescope unlock` on the hub host.
- Rollback: one-way for the config. Given a converted config, 1.4.2
  either refuses it (when it uses `"off"`) or, worse, ignores `host`
  without error and runs with no host checks. Roll back the config along
  with the binary. On NixOS, a generation
  rollback does both. Elsewhere, keep the 1.4 config next to the 1.4.2
  binary and restore them together.
- Verify: the footer and `/status.json` show `1.5.0+<rev>`, and the check
  count is the same as before the upgrade.
