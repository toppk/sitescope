# sitescope 1.7.1

The agent on FreeBSD and OpenBSD. A BSD host can now be watched from the
inside, by its own agent or as a hub's local host, and a BSD hub can ping
without root. Linux hosts get exactly the checks and names they had.

## Features

- The agent runs on FreeBSD and OpenBSD, as an ordinary user. Give the host
  `os = "freebsd"` or `os = "openbsd"`; that picks its checks.
  - **Same checks as on Linux, same names:** disk, memory, swap, load,
    CPU, network, WireGuard, named services (`unit.NAME`) and package age.
    Memory counts free plus inactive pages as available. CPU comes from
    `kern.cp_times` (FreeBSD) or `kern.cp_time` (OpenBSD). Network comes
    from `netstat`, with drops on FreeBSD only.
  - **Reboot needed (FreeBSD and Linux):** `freebsd-version -k`
    (installed) against `-r` (running). OpenBSD has none, because it
    relinks its root-only `/bsd` at every boot.
  - **Failed rc services (OpenBSD only):** enabled daemons that aren't
    running, under the check id `host.HOST.units`, where Linux has failed
    systemd units. FreeBSD's rc keeps no failed state, so a FreeBSD host
    names the services that must run in `units` instead.
  - **Linux only:** memory pressure, disk I/O, and service memory
    (cgroups). A BSD host doesn't get those checks.
- A host's `units` names rc services on the BSDs, such as `sshd`, checked
  with `service NAME status` or `rcctl check NAME`. Timers, `user` and
  `maxAge` stay Linux only, and the config check refuses them on a BSD
  host. On FreeBSD, a service whose pid file only root can read, such as
  `cron`, is found by its exact process name, and the message says so.
- A `local = true` host works on a BSD hub. Its `os` must name the hub's
  own system, or the hub refuses to start.
- Ping on FreeBSD and OpenBSD falls back to the system's setuid
  `/sbin/ping` (or `/sbin/ping6`) when the hub isn't root, one echo a
  second. Root still uses a raw socket.

## Bug fixes

- The `dns.resolve.NAME` checks are listed in name order. They were built
  from a map, so their order on the detail page could change between
  restarts.

## Breaking changes

None.

## Upgrade notes

- Nothing changes for Linux hosts or their configs.
- On a BSD agent, start it after `wg0` has its address: the BSDs have no
  `IP_FREEBIND`.
- Rollback: two-way; the report format only gains values on the BSDs.
- Verify: the footer and `/status.json` show `1.7.1+<rev>`.
